# diag_cs1_store_upgrade: an older committed store upgrades a squashed load's install to M, CleanupSpec skips the cleanup, the victim is never restored (CS-1)

**Issue and signature.** On CleanupSpec (`/work/amulet/amulet-gem5-CleanupSpec_AE-v1.1`, `Cleanup_FOR_L1L2`), a squashed load S misses L1D, installs line L in E and evicts victim V. An older store U (older than the squashing branch, committed) then writes L from the store buffer: `L1D:hit line=L … req=st … st=E:nst=M`. At the squash S's cleanup finds L in M and skips everything (`L1D:cleanup_skip line=L seq=S … ev=Inv_CLEANUP:st=M`), so V is never restored. check_footprint's ownership rule moves L to U (no install term) but keeps V charged to S, so the record is a victim-only `under_clean`. Signature, per offending item: cause `CS1_older_store_upgrade` in `cleanupspec_skip_evidence.json` (built by `STAGE3_gem5/triage/cleanupspec_skip_evidence.py`); the stem is bucketed only if every item of every hitting variant has that cause.

**Evidence.** Example (control warm run `STT_6_rmwstems_cleanupspec_footprint_ctrl_warm__20261109_060609`, `mispredict_not_taken/inst-043313`): `3870000 L1D:evict line=0x3580 seq=568 victim=0x3980` and `L1D:fill line=0x3580 seq=568 … st=NP:nst=IS` (S = `ld rax,[rsi]` at 0x401c68, never retired); `3870500 L1D:hit line=0x3580 seq=561 pc=0x401c53 req=st … addr=0x35bf size=1 st=E:nst=M` (U = the last-committed store `movq %rdi,(%rsi,%rax)`, committed at 3863000, drained only after S's fill because S's GETS held the line's MSHR); `6362000 ROB:squash seq=566`; `6363000 L1D:cleanup_skip line=0x3580 seq=568 … ev=Inv_CLEANUP:st=M`; no `cleanup_restore` of 0x3980. Same chain in inst-072476 and inst-074723 (both modes) and in the E13 hits inst-101824 / inst-102050. Code: `MESI_Two_Level-L1cache.sm:2701-2705` `transition(M, Inv_CLEANUP) { clirs2_cleanup_L12InvRoll_skip; … }`.

**Verdict.** Not a real defense bug by the paper's own rule: CleanupSpec §3.4 p7 says changes made by older non-squashed accesses that execute after squashed loads "need to be preserved … corresponding invalidations / restorations are skipped", which is what the code does. Whether the leftover victim is a leak is a criterion question, Anna's open DECIDE (URGENT_TODO "CS-1 un-charge the victim"): with random L1 replacement the store would have evicted a random line of the same, architecturally known set anyway, so the victim's identity carries no information (an argument, not a measurement). Hence `PHASE = "known_pending"`: the hit is explained and kept out of NEW, but not called an artifact or a bug until Anna decides. Scope: build behaviour, so every CleanupSpec footprint campaign (each needs its own evidence file).
