# diag_uv4_split: CleanupSpec never cleans a squashed line-crossing load (AMuLeT UV4)

**Issue and signature.** On CleanupSpec (`/work/amulet/amulet-gem5-CleanupSpec_AE-v1.1`, `Cleanup_FOR_L1L2`), a squashed load whose access crosses a cache line (split request) installs lines in L1D (and sometimes L2) and evicts an L1D victim; the cleanup loop skips it outright (`L1D:cleanup_skip … seq=S why=split`), so neither the installs nor the victim are undone. Signature, per offending item: cause `UV4_split` in `cleanupspec_skip_evidence.json` (built by `STAGE3_gem5/triage/cleanupspec_skip_evidence.py`): the item's event is a fill or an evict by an actor S that never committed, and S has a `why=split` skip. The stem is bucketed only if every item of every hitting variant is UV4.

**Evidence and root cause.** `cpu/o3/lsq_unit_impl.hh:2529-2535` in `issueBufferedCleanupReqs`: `if(loadQueue[load_idx]->isSplitReq()){ … //TODO: Cleanup For SplitReq … setSquashBuffered(false); //Cleanup Done }`. Example (RMW warm run `STT_6_rmw_cleanupspec_footprint__20261109_002545`, `mispredict_taken/inst-021314`): the split load seq 572 fills L1D and L2 line 0x3580, evicts 0x3780, and its cleanup is `why=split`. The cache-setup classifier called these records `UV4_split_plus_other`; the "other" item is always the victim evicted by the same split load (7/7 stems in each warm run, 2026-11-09), so the whole record is UV4.

**Verdict.** Real gem5 defense bug, already known (AMuLeT UV4); it violates CleanupSpec §1 p2 ("the perceived cache state after these operations is as if the transient loads did not access the cache"). Not a checker artifact. Scope: build behaviour, so every CleanupSpec footprint campaign (each needs its own evidence file).
