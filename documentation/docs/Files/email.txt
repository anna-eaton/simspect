Nick, 
you can find the gem5 repo here: https://drive.google.com/file/d/1TWawzRXjXL3YHaUhTIT03tA5sdFbvYtm/view?usp=sharing. 
The code is a kind of a mess (there is also some dead code in there since the repo is running for quite a long time now), so in case you really want to look at the code, I would suggest emailing me and not waste your time trying to figure out what happens in there :)
Quick info that you may need for your evaluation: the current repo supports shadows occurring from control and store instructions -- you can find them in the decode file in o3 folder -- in case you want to test only the spectre theat model (disable the store shadows -- just comment out line 690).  
To run different schemes you just add a parameter to gem5 command line: --scheme. --scheme 0 corresponds to the unsafe baseline, --scheme 1 to NDA, --scheme 2 to STT (the one you will need) and --scheme 3 to DoM 
Let me start with doppelganger which is super trivial to run (even if you may not even need it), you just run your normal command lines with simple memory (no --ruby cause it will crash), and in the command line you just add --address_prediction. This will run the predictor with the default parameters as it was in the paper). So if you want to run STT + Doppelganger all you do is add to your command line --scheme 2 --address_prediction.
Now for ReCon, since it modifies SLICC and its not trivial to pass parameters from the CPU in there (and I am too lazy for that), you will find two ruby folders. One being the default/clear ruby and the other one being ReCon (a folder in the gem5 directory named ruby-versions -- ruby-default is the default -- ruby-singlecore is ReCon). I have not included parallel since I assume you will not run it, and it gets more complicated to run, so if you need it let me know. Now to run recon you need to add --allow_leaked, in the command line. That is, for STT+ReCon you just add --scheme 2 --allow_leaked.
What I usually do is compile one of the random gem5 opts (e.g., X86_MI_example) with the baseline (ruby-default), and then compile another opt (e.g., X86) for ReCon (ruby-singlecore), so that I have a compiled version of baseline and do not really need to recompile again. To compile obviously you need to enable the MESI_Three_Level protocol. (scons build/X86/gem5.fast -j 20 PROTOCOL=MESI_Three_Level).
So to summarize, remove the ruby folder (src/mem/ruby). Use the ruby-default as ruby (in the same path), and run your command line with --scheme 0 (unsafe baseline), and --scheme 2 (STT). Use the ruby-singlecore as ruby, and run your command line with --scheme 2 --allow_leaked (STT+ReCon). Then normalize to unsafe baseline STT and STT+ReCon and vuala! 
One of my command lines for example would look like this: ./build/X86/gem5.fast --outdir=...    --redirect-stdout --redirect-stderr ./configs/example/fs.py    --restore-simpoint-checkpoint    --checkpoint-dir=...     -r ...     --kernel=...    --disk-image=...     --script=...    --caches --cpu-type=DerivO3CPU     --l0d_size=65536 --l0i_assoc=8    --l0d_assoc=8 --l0i_size=65536    --l1d_size=2MB --l1d_assoc=16    --l2_size=16MB --l2_assoc=32    --ruby    --enable-prefetch     --mem-size=8GB --cpu-clock=3GHz    --cacheline_size=64    --scheme 2    --allow_leaked 
If I dont forget anything essential, thats more that enough to run it. Let me know how it goes, and of course if you encounter any problems, just email me, do not waste too much of your time as the deadline is approaching!

Pavlos.
