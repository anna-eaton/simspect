## InvisiSpec (Yan et al., MICRO 2018; build = AMuLeT AE copy of InvisiSpec-1.0)

## Mismatches and surprises

1. **InvisiSpec directory: a USL can invalidate an M owner.** `IS/.../MESI_Two_Level-dir.sm:499-503` handles `SpecFetch` in M with `inv_sendCacheInvalidate`, under the authors' own comment `// [InvisiSpec] Is it secure?`. The paper says Spec-GetS changes no coherence state (§VI-E1 p9). Single-core runs can still show it as an L2/DIR transition.
2. **InvisiSpec D-TLB: only the miss half is implemented.** Miss → fault, no fill (`tlb.cc:381-392`); hit → `lookup()` updates `lruSeq` for USLs too (`tlb.cc:146-150`, default `update_lru=true` at `tlb.hh:74`). Paper §VI-E3 p9 defers hit-side replacement updates. AMuLeT's 1-page sandbox (p7) cannot see either half. This explains the criteria session's `DTLB:repl_touch` events on squashed InvisiSpec loads (claudelog 2026-10-28 "criteria"): the code shows this build does update D-TLB LRU on a USL hit, so those events are consistent with a real build-vs-paper deviation rather than a hook attribution artifact (not confirmed per event). Mismatch 1 is a candidate source for its `L2/DIR:coh` events (not checked against those traces).
3. **`allowSpecBuffHit` is off in AMuLeT's InvisiSpec runs.** `CpuConfig.py:107-110` turns it off when the flag is omitted, and AMuLeT never passes it. Ours pass `=1`. AMuLeT also used `--needsTSO=0` (`executor.py:295`), ours `=1`.
