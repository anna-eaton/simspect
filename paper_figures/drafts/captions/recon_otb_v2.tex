\textbf{Recon-STT releases a transmitter whose address still depends on a speculative load} (\texttt{getOldestTaint}; \texttt{/work/gem5-recon}, STT scheme, hand-built test). Top: the test as an execution graph in the notation of Table~X. The ALU op i4 merges $r_0$ from the older load i1, speculative under branch i0, with $r_1$ from the younger load i3, speculative under the mispredicted branch i2; its result is the address of transmitter i5 (thick arrows: the flow from i3). Bottom: the gem5 pipeline trace (cycle = (tick $-$ 2803000)/500). i0 resolves at cycle 0, and i5 issues at cycle 8 ($\star$), as soon as i4's result is ready and at the same cycle as with no defense, while i2 stays unresolved until cycle 92. Recon gives i4's result only the taint of its oldest tainted source and frees it when that source stops being speculative (blue), so the dependence on i3 is lost. This test was built by hand; our bounded enumeration does not reach this shape within its instance cap.
