## 1. The Recon STL bug (`reconstl_v2`)

**What it is.** On Recon's STT (gem5-recon-modded, `--scheme=2`), a load whose address is tainted completes by store-to-load forwarding (STLF) before the squash, although STT must hold it. Recon's taint check for loads sits only on the cache path of `LSQUnit::read()`; the STLF path copies the store's data, schedules the writeback and returns first (`lsq_unit.cc` ~1950-2030 return vs. the taint check at 2090-2103; `WritebackEvent::process()` at 194-212 checks the Delay scheme but not STT). Source: `wiki/results/reconresults.md` "Bug 2". These line numbers are from a code read on cafe2 (`/work/gem5-recon`), not re-read this session (the tree is not on the Mac).

**Why it is a bug against STT's own spec.** STT treats STLF as an implicit branch: the forwarding decision depends on the load's address, so its resolution must wait until the address is untainted (Yu et al. 2019, Sec. 6.4.2 and Fig. 9, p. 8). Its optimization (Sec. 6.5, p. 9) still issues the load only once its address is untainted and writes the output only after the memory access completes, "to guarantee that the timing of younger instructions is unchanged from the no forwarding case". Recon lets the tainted load finish early with forwarded data, so completion timing depends on whether a tainted address matched an in-flight store. Paper read locally: `~/Documents/quail/sources/papers/yu-2019-stt.pdf`.

**Evidence (real trace, the one the figure draws).** `wiki/findings/bug/recon_SLF_stlf_bypass/` (`NOTE.md`, `provenance.json`, `trace_excerpt_sn600.txt`, `inst-014912.{s,ann.json,xml}`). Campaign `results/Recon_6__20260602_122016` (cafe2; not on the Mac), `mispredict_not_taken`, ld. Trace lines (cycle = (tick − 2679000)/500): store sn 599 and xmit sn 600 inserted at 2679000 (0); both execute at 2681500 (5), store writes addr 0x35c0; `STL_CHECK: load PC 0x401c7c isTainted=1 isSpeculative=1` at 2681500 (5); store ready 2682000 (6); xmit "ready within ROB" 2682500 (7); both squashed 2683500 (9). An earlier hand-built pair on vanilla `/work/gem5-recon` (`STL_bug/inst-008297.s`, `inst-000637.s`, May) has the same shape (`reconresults.md`).

## 2. The visibility-point/squash race (`squashrace_v2`)

**What it is.** STT (`/work/stt`) stops tainting a load's result once all older branches have resolved (`rob_impl.hh` `compute_taint` 812-814, `updateVisibleState` 519-520, per `wiki/findings/bug/stt_slowcomm_vp_squash_race/BUG_EXPLAINER.md`). On a mispredict, resolution also starts the squash, which needs `commitToIEWDelay` cycles to reach the LSQ; the now-untainted wrong-path transmitter issues in between.

**Evidence.** `wiki/findings/bug/stt_slowcomm_vp_squash_race/` (inst-047231, experiment `slow_comm_squash1`, `se_slowcomm.py`, commitToIEWDelay = 4). Ticks (cycle = (tick − 2907000)/500): lc retires 2907000 (0); xmit sn 571 inserted 2930000 (46); first issue 2931500 (49), held; branch 0x401c51 resolves 2945500 (77); re-issue 2946000 (78); `successfully sent out packet(s)` 2946500 (79); squashed 2947500 (81); fnc retires 3037500 (261). Sources: `provenance.json` "evidence", `example_inst-047231.md:46-50, 96-98`. Stock timing: no leak (0/1200, `provenance.json`); trigger table in `BUG_EXPLAINER.md` (leaks from commitToIEWDelay 3, or 2 with iewToCommitDelay 2).

**Pre/post harness fix.** Predates the fix. `/work/stt` did load annotations (the zero-annotation bug was gem5-spt and gem5-recon-modded), and this test is `mispredict_not_taken` with a natural mispredict (`movq $1,%rsi; testq; jne`), so the trace is probably unaffected. Still, the folder says it was copied, not re-verified, and no fixed-harness slow-comm run exists. Round 2 STT_6/stt 0 hits is at stock timing, which agrees with the claim.

**Window caveat (important).** The packet (79) comes after the branch resolves (77). The post-fix check_ld requires every unresolved branch to still be unresolved at the signal (`STAGE3_gem5/check_ld.py:110-114`, `gem5_common.check_branch_resolutions`), and figure (e) draws the window as "lc retires → branch resolves". Under that definition this race is **not** a violation; it was counted under the older `(lc_retire, fnc_retire)` window. The figure draws the committed window and says so; see Decision R1.

## 6. Suggested paper text (results section; Anna pastes, Claude does not edit the paper)

**Recon (new paragraph).** We also ran SimSpect on ReCon's gem5 implementation of STT, which treats both unresolved branches and stores with unresolved addresses as sources of speculation. It exposes a bug in how ReCon applies STT's load rule: ReCon checks a load's taint only on its cache path, after store-to-load forwarding has already returned. A speculative load whose address is tainted therefore completes with a forwarded value whenever an in-flight store has the same address (Fig.~\ref{fig:reconstl}). STT names exactly this case an implicit branch and requires the forwarding decision to wait until the address is untainted, or the forwarded value to be written only when the memory access would have completed [STT, §6.4.2, §6.5]. The completion time of the load therefore reveals whether a secret-derived address matches a store address the attacker chose.

**Recon OTB (if kept).** ReCon's taint tracker also keeps only the oldest taint source when an instruction merges two tainted operands. When the older source's branch resolves, the result is untainted even though it still depends on a younger speculative load, and a dependent transmitter issues. We confirmed this with a hand-built two-branch test; our bounded enumeration does not reach this shape within its instance cap.

**Race (revised framing; depends on R1).** In STT, a transmitter's address stops being tainted the moment every older branch resolves. When that branch was mispredicted, the same event starts the squash, which reaches the load queue `commitToIEWDelay` cycles later. In inst-047231 the held transmitter issues one cycle after resolution and sends a cache packet two cycles before its squash (Fig.~\ref{fig:race}). At stock timing the squash wins.

**Caveat (pre-fix numbers).** The counts in this section (race instances, the stall and fragility sweeps, SpecLFB detection speed) come from campaigns run before we fixed the branch-annotation and resolve-stall harness on 2026-10-30; on the SPT and ReCon builds those campaigns ran without the intended forced mispredicts and stalls. We are re-running them; the two traces shown here do not depend on the fix, since their mispredictions occur naturally.
